Install

Running in a minute.

Prebuilt for macOS and Linux, on x86_64 and arm64.

curl --proto '=https' --tlsv1.2 -LsSf https://github.com/dayvson/crabcrop/releases/latest/download/crabcrop-installer.sh | sh
  1. Start the server with a new secret. 
    export CRABCROP_SECRET="$(openssl rand -hex 16)"
CRABCROP_ALLOW_UNSAFE=1 crabcrop
# crabcrop listening on port 3000
  2. Request an image: a source photo at 300 by 200. 
    curl "http://localhost:3000/unsafe/300x200/https://example.com/photo.jpg" \
  --output photo.jpg
  3. In production, drop the unsafe switch and sign the URL. 
    curl "$(crabcrop sign 300x200/https://example.com/photo.jpg)" --output photo.jpg

Anatomy

Three parts, always in this order.

Every image request is GET /<signature>/<operations>/<source>. That strip is the whole grammar.

https://img.example.com/5b9fc0ad…/crop:1200x630:smart/filters:grayscale/https://example.com/photo.jpg

  1. Signature 1 of 3

    Proof the URL came from you. The server recomputes the HMAC-SHA256 over the operations and the source exactly as they appear. A match serves the image. A miss gets a 403.

    A sealed URL keeps its whole recipe in this slot, as one opaque token.

    5b9fc0ad…s1.<token>

  2. Operations 2 of 3

    Zero or more segments, applied in path order. Resize, crop, fit-in, and pad are their own segments. Filters chain inside one filters: segment.

    An expiry and a server-side preset are segments too.

    300x200crop:1200x630:smartfilters:grayscale:format(webp)exp:1893456000preset:og-card

  3. Source 3 of 3

    It starts at the first segment that is not an operation and may contain slashes. A full URL works, and so does a short root: reference the server expands against its own origins.

    A video or a PDF works as a source. A segment picks the frame or the page.

    https://example.com/photo.jpgroot:photos/print.jpgframe:50%page:2

What it does

Everything an image pipeline does, in one signed URL.

Each tile shows the segment that asks for it. The pictures are the examples from crabcrop.org.

Smart crop, face safe

The crop window finds the subject and keeps detected faces whole instead of clipping them at the edge. A YuNet model finds the faces, and :face crops to the largest one.

crop:760x760:smartcrop:760x760:face

Studio mode

The listing shot in one filter: cut out, backdrop, contact shadow, margin. Backdrops resolve on the server: your brand color by default, or white, or none.

Or keep the photo: scene mode reframes on the subject and corrects the light and color.

filters:studio(product)filters:studio(scene)

Background removal

Your ONNX model, in process. The subject stays and the background becomes real alpha.

filters:removebg:format(webp)

Redaction

Blur or pixelate faces, or every detected object of a class. Redaction never guesses: a detection failure fails the request.

filters:blurclass(person)filters:blurfaces

All major formats, in and out

In and out
JPEG, PNG, WebP, GIF, AVIF, JPEG XL
Decode only
HEIC, HEIF, TIFF, BMP, ICO, SVG

Name no format and the Accept header decides: AVIF first, then JPEG XL, then WebP. An explicit format always wins.

filters:format(avif)

51 filters, one chain

Resize, crop, fit-in, and pad are their own path segments. The 51 filters chain inside one filters: segment and run in the order written.

filters:sharpen(1.2):saturation(1.1)

More than photos

The input does not have to be a photo. crabcrop decodes one frame of a video or one page of a PDF and serves it as an image, like any other source.

frame:50%page:2

Sources, wherever they live

The source in the URL can be a plain https address, an object in S3 or GCS, a file on local disk, or a short root: reference the server resolves against the storage you configured.

s3://bucket/keyroot:photos/print.jpg

Metadata that describes the picture

Send Accept: application/json with any image URL and the answer is JSON about the render instead of its bytes. Meta mode is off by default.

Opt-ins add CLIP tags and alt text, detections, moderation verdicts, embeddings, an aesthetic score, and OCR text.

CRABCROP_META_MODE=1Accept: application/json; ocr=1

The example from the docs

# With CRABCROP_META_MODE=1 on the server
curl -H "Accept: application/json" \
  "http://localhost:3000/unsafe/300x200/https://example.com/photo.jpg"

{
  "width": 300, "height": 200, "format": "jpeg", "bytes": 18234,
  "source_width": 1200, "source_height": 800
}

Sealed URLs

For links that stay public but unreadable. The whole recipe, operations and source, is encrypted into one opaque token in the signature slot. Only the server opens it.

s1.<token>/photo.jpg

Presets and purge

Server-side preset names keep templates short. Purge one result, or a whole preset group, with signatures from their own subkey.

preset:og-cardPOST /purge-group

Provenance, checked and signed

Meta reports the C2PA Content Credentials a source carries. With your own certificate, still JPEG, PNG, WebP, and AVIF outputs are signed as served.

CRABCROP_C2PA_CERTCRABCROP_C2PA_KEY

URLs that explain themselves

Put explain/ in front of any signed URL and the server reports on it, segment by segment, instead of serving the image.

GET /explain/<signature>/...

Signing

Sign a URL from any stack.

Every URL carries an HMAC-SHA256 signature over the operations and the source, in lowercase hex. Same inputs, same URL, whichever of these you use.

printf '%s' 'crop:1200x630:smart/filters:grayscale/https://example.com/photo.jpg' \
  | openssl dgst -sha256 -hmac 'demo-secret'
# SHA2-256(stdin)= 5b9fc0ad8492552ef2c0c8af53d26851f958a213d95b1024754a311f48443e05
import { buildURL } from "@crabcrop/url";

const url = buildURL(
  "https://img.example.com",
  "demo-secret",
  "crop:1200x630:smart/filters:grayscale",
  "https://example.com/photo.jpg",
);
from crabcrop_url import build_url

url = build_url(
    "https://img.example.com",
    "demo-secret",
    "crop:1200x630:smart/filters:grayscale",
    "https://example.com/photo.jpg",
)
use crabcrop_url::build_url;

let url = build_url(
    "https://img.example.com",
    Some(b"demo-secret"),
    "crop:1200x630:smart/filters:grayscale",
    "https://example.com/photo.jpg",
    None,
)?;

Each snippet signs the same example with the sample secret demo-secret. Swap in your base, your secret, and your operations.

An MCP server for coding agents

The repo ships a first-party MCP server over the same SDK and HTTP surface. It runs on stdio and needs nothing else installed.

  • sign_urlBuild a signed URL, checked against the server grammar.
  • explain_urlExplain a URL segment by segment and verify its signature.
  • fetch_metaFetch the meta JSON for an image URL.
  • purge_resultPurge one cached result by its path.

MCP config

{
  "mcpServers": {
    "crabcrop": {
      "command": "npx",
      "args": ["-y", "@crabcrop/mcp"],
      "env": {
        "CRABCROP_BASE": "https://img.example.com",
        "CRABCROP_SECRET": "your-secret"
      }
    }
  }
}

Production

Ship it where you already run.

One recipe per platform and one per CDN, each a complete walkthrough in the repo. Every recipe follows the same flow: create the signing secret, deploy, run the smoke checklist.

Platforms

Run crabcrop behind a reverse proxy or a CDN.

  • Kubernetes, Helm chartOne replica by default. A multi-replica values file ships with the chart.
  • Kubernetes, kustomizeA base, with components for presets, result storage, and the AI variant.
  • AWS, ECS FargateA Fargate service behind an Application Load Balancer.
  • GCP, Cloud RunA Cloud Run service, with one instance kept warm.
  • Azure, Container AppsAn app with ingress, with one replica kept warm.
  • Docker ComposeA one-command evaluation run on a single host.
  • A VMThe release binary and a systemd unit, behind a reverse proxy.

CDNs

Optional, after any platform.

  • CloudflareCache rules, and purges mapped to cache tags.
  • CloudFrontA cache policy that respects origin headers, and an edge function that normalizes Accept.
  • FastlyCache groups bridged to surrogate keys for group purges.
  • BunnyCDNCache groups bridged to CDN tags by a middleware script.
  • AkamaiCache groups bridged to cache tags by per-preset rules.

Built to say no

The server bounds its own work.

  • A size capOutputs stop at 16383 px per axis and 100 megapixels. A request past either bound fails with 400 before anything is allocated.
  • An operation capA request runs at most 100 operations.
  • Overload is shedThe processing, slow-lane, AI, video, and animation gates shed overload with 503.
  • Private addresses are refusedA source that is, or resolves to, a non-public address gets 403 source_forbidden. On by default.
  • A bad signature is a 403So is a signed URL past its exp: second.

Speed

Blazing fast, in numbers.

A first request does the whole job: fetch the source, decode it, transform it, encode the answer. These are medians from the benchmark kept in the repo, and crabcrop leads or ties eight of the ten operations.

How it was measured

Every server got the same 25 source images and the same ten operations, served from one local origin. Cold means the first request for each image, before any cache can help. Each figure is the median of repeated runs.

Measured 15 November 2026. crabcrop 0.13.0, imgproxy 4.0.24, Thumbor 7.8.0. Host: one small shared VM, 4 cores (AMD EPYC 9D25), 7.7 GiB RAM, Ubuntu 24.04.5 LTS. Small differences are noise; the rankings are the robust part.

The harnessFull results and raw data

Warm repeats, briefly

Repeat requests matter less than they look: a CDN in front of any of these servers serves most repeats before they arrive. crabcrop answers warm repeats at a 0.2 to 0.4 ms median on every operation, and its warm resize throughput medians 1,874 requests per second at 8 workers. Thumbor medians 25.8 and imgproxy 56.0, neither caching results in these configurations. The full warm data is in the raw JSON beside the results document.
