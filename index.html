On-demand image optimization, in Rust

The URL is the API.

crabcrop resizes, crops, converts and filters your images on demand. You encode the operations in the URL, sign it, and crabcrop fetches the source, does the work, and returns the result. No pre-generated thumbnails. No build step.

Try the live demos See signed URLs in code

Signed with HMAC-SHA256. Cached by canonical key. Served with Cache-Control: immutable for a year.

https://img.example.com/3c1f6c18…/crop:1200x630:smart/filters:grayscale:quality(80)/https://example.com/photo.jpg

How it works

Three parts. One request. Zero setup per image.

Every image request is GET /<signature>/<operations>/<source-url>. Change the operations and you change the image. The signature keeps the menu under your control, and signed URLs are content addressed, so results cache cleanly in memory and on disk.

✂️

Resize, crop, fit, pad

Exact sizes like 300x200, proportional sizes like 300x0, fit-in boxes, pad with a color or ambient blur fill, aspect crops with smart and face alignment, and exact rectangle crops.

🎛️

45+ filters and directives

Grayscale, sepia, duotone, blur, sharpen, saturation, radius, borders, masks, watermarks, overlays with blend modes, and text labels. Chain them inside one filters: segment, in the order you write them.

🗜️

Modern formats, negotiated

Output JPEG, PNG, WebP, JPEG XL, AVIF or GIF. Name a format in the URL, or let the Accept header decide: the highest q-value wins, with AVIF, JPEG XL and WebP as the tie-break order.

🔐

Signed and expiring

HMAC-SHA256 signatures cover the operations and the source. Add an exp: segment and the URL expires on schedule. Purges have their own domain-separated signatures, so an image signature can never be replayed as a purge.

🏷️

Presets keep URLs short

Name an operation string on the server, like preset:og-card, and templates stay short while the transformation menu stays operator controlled. Roll changes out under a new preset name.

🧹

Purge in one call

Invalidate one result with /purge, or a whole preset output set with /purge-group and the Cache-Group header. Equivalent spellings of a path share one canonical cache entry, so one purge evicts them all.

Sign it in your stack

One signing scheme, every language.

The grammar and signing scheme are specified once, with a canonical set of test vectors that every implementation runs as its test suite. The server verifies with the same Rust crate your app builds with, so client and server cannot drift.

# Sign the remainder with openssl, then use the hex as segment one
printf '%s' '300x200/https://example.com/photo.jpg' \
  | openssl dgst -sha256 -hmac 'your-secret'
# SHA2-256(stdin)= 3c1f6c180116661877bd4c85fd201a178087d74c1cc188cc584e819d901308c6

curl "https://img.example.com/3c1f6c18…/300x200/https://example.com/photo.jpg"
// @crabcrop/url, standard library only
import { buildURL, buildSrcSet, purgeSignature } from "@crabcrop/url";

const url = buildURL({
  base: "https://img.example.com",
  secret: process.env.CRABCROP_SECRET,
  operations: "crop:1200x630:smart/filters:format(webp):quality(80)",
  source: "https://example.com/photo.jpg",
});

const srcset = buildSrcSet({ /* same options */ }, [400, 800, 1200]);
# crabcrop_url, standard library only
import os
from crabcrop_url import build_url, build_srcset, purge_signature

url = build_url(
    base="https://img.example.com",
    secret=os.environ["CRABCROP_SECRET"],
    operations="300x200/filters:grayscale",
    source="https://example.com/photo.jpg",
)

srcset = build_srcset(..., widths=[400, 800, 1200])
// crate: crabcrop-url, the same crate the server verifies with
use crabcrop_url::{build_url, sign};

let signature = sign(secret, "300x200/https://example.com/photo.jpg");
let url = build_url(base, secret,
    "crop:1200x630:smart/filters:format(avif):quality(auto)",
    "https://example.com/photo.jpg")?;

Beyond the transform

Metadata, placeholders and responsive help, built in.

🧾

Meta as JSON

Send Accept: application/json on any image URL and get dimensions, format, byte size and source size instead of image bytes. Grammar errors answer with a stable JSON error envelope.

🎨

Placeholders while it loads

Ask for placeholders and meta adds the dominant color, a five-color palette, a tiny blurred JPEG preview, and a ThumbHash string your client can decode into an aspect-correct blur.

📐

Quality you can verify

quality(auto) picks per image, then for JPEG and JPEG XL it encodes, decodes and scores the result with SSIMULACRA2 until it lands on target. The score is reported back in meta.

📱

Client hints and DPR

URLs that size nothing can take width from client hints, quantized so nearby viewports share a cache entry. dpr(2) serves retina from the same template, and Save-Data steps quality down for visitors who ask.

🗄️

Sources where they live

Fetch originals over HTTP and HTTPS, from S3 or S3-compatible stores, from Google Cloud Storage, or from a local file root. EXIF orientation is applied at decode, so phone photos come out upright.

🛟

Graceful by design

An optional fallback image serves through the same operations when a source fails. Signature and parse errors stay honest, and fallback responses are never cached, so a recovered origin is picked up on the next request.

Warm throughput, resize, 8 workers

Signed URLs are content addressed, so successful responses cache in a byte-bounded in-memory LRU, with an optional disk tier underneath that survives restarts. Only 200 responses are cached. Errors never are.

AI features

Models you supply. Inference in process.

AI features run ONNX models you provide as deployment artifacts. crabcrop never downloads a model. Models load at boot and fail fast if they cannot, and inference runs behind a bounded gate so AI requests cannot starve the normal pipeline. No model configured means a clean 501, never a silent fallback.

🪄

Background removal and upscale

filters:removebg keeps the subject over transparency. filters:upscale(2) or upscale(4) runs super-resolution, capped at 4096 px per dimension, with source transparency carried across.

🙂

Face-aware crops and redaction

A face model makes crop:...:smart center on faces and powers crop:...:face. blurfaces and pixelatefaces redact every detected face. A detection failure fails the request rather than serving an unredacted image.

🚗

Class redaction

With a detection model, blurclass(person) and pixelateclass(car) redact every detected object of a class. Repeat the filter for more classes. Meta can return the detection boxes for debugging.

🏷️

Tags and alt text from CLIP

With a CLIP model pair configured, meta responses gain zero-shot tags with scores and a short alt_text composed from the best labels. Phrase-style labels work, and labels are embedded once at boot.

Libraries and tools

Build URLs from anywhere. Even from your agent.

🦀

Rust crate

crabcrop-url with sign, verify, URL and srcset builders, and purge helpers. The same crate the server verifies with.

🟦

TypeScript

@crabcrop/url, standard library only. Sign, verify, build URLs and srcsets, and compute purge signatures.

🐍

Python

crabcrop_url, standard library only. The same builders and purge helpers, tested against the same vectors.

🤖

MCP server for coding agents

A first-party MCP server over the same SDK and HTTP surface, exposing sign_url, explain_url, fetch_meta and purge_result.

⌨️

Operator CLI

The server binary doubles as its own CLI: sign, explain, meta, purge and purge-group. URLs are validated against the server grammar before they are signed.

🧩

Framework loaders

A Next.js custom loader for next/image, a Nuxt provider for @nuxt/image, and a Hydrogen loader for external images. All three recommend presets, so client-side building never needs the secret. A browser playground builds, signs and explains URLs with the secret never leaving the page.
