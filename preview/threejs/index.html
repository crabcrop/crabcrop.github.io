Scroll, and the picture resolves.

crabcrop is an on-demand image service written in Rust and released as open source. It resizes, crops, converts, and finishes photographs straight from a signed URL, on a server you run yourself. One binary. No pre-generated thumbnails, no build step.

One URL runs the whole pipeline.

This page is the demo. Each plate below performs the operation it describes as it crosses your screen, driven by the scroll you are already making. What crabcrop does to a photograph inside one request, the scroll does here in the open: the recipe grades the color, the model lifts the subject out of its backdrop, the upscale rebuilds the detail.

Color, graded by the recipe.

The recipe is written in the URL itself. Resize, crop, fit-in, and pad are their own path segments, and the 51 filters chain inside one filters: segment, everything running in the order written.

Server-side preset names keep templates short, and each format takes its own encoder settings, so the same source can be finished a dozen ways without a single file stored in advance.

Keep scrolling and the plate follows the recipe: grayscale in, full color out, exactly the operations the URL names. Nothing here is a screenshot of the effect; the effect is the scroll.

The subject stays. The backdrop lets go.

Background removal runs your ONNX model, in process. The subject keeps its edges; the background becomes real alpha, ready for whatever sits behind it.

Studio mode takes the next step in the same request: cut out, a clean backdrop in your brand color, a soft contact shadow, and a margin. The listing shot in one filter.

No model configured means a clean 501, never a silent fallback. The plate is honest about the trade: as the scene dissolves, what remains is exactly what the alpha channel keeps.

Detail, rebuilt.

AI upscale runs a super-resolution model you supply. upscale(2) or upscale(4) rebuilds detail instead of stretching pixels, and source transparency carries across.

It never falls back to a plain resize. If the model cannot run, the request fails in the open rather than quietly serving a blurrier picture under the same URL.

The plate starts as a handful of blocks, the way a small source arrives. What finishes is the full frame, because the model fills in what the source only suggests.

Smart crop keeps the subject whole.

The crop window finds the subject first, and keeps detected faces whole instead of clipping them at the edge.

The rest of the pipeline, in the same URL.

Everything below rides in the same signed URL as the stages above. No second API, no job queue, no stored derivatives.

All major formats, in and out

JPEG, PNG, WebP, GIF, AVIF, and JPEG XL, in and out. HEIC and HEIF decode only; SVG decodes, sanitized and rasterized. Name no format and the visitor's Accept header decides: AVIF first, then JPEG XL, then WebP. An explicit format(...) always wins.

format(avif) · format(jxl) · frame:50% · page:2

More than photos

The source can be one frame of a video, one page of a PDF, an object in S3 or GCS, a local file, or a short root: reference the server expands against its own origins. Originals can also arrive through the signed upload endpoint, off by default.

root:photos/cat.jpg · PUT /upload/<name>

Redaction that never guesses

Blur or pixelate faces, or every detected object of a class. A detection failure fails the request rather than serving an unredacted guess. With a segmentation model, class redaction follows the object's silhouette instead of its box, and recolorclass paints it a solid color.

filters:blurclass(person) · filters:recolorclass(car,ff0000)

Metadata that describes the picture

JSON meta for every render: dimensions, format, byte size, provenance. The richer answers are opt-ins with their own model sets: CLIP tags and alt text, detections, moderation verdicts, embeddings, an aesthetic score.

Accept: application/json; detections=1

Reads the text in the picture

Opt a meta request in and the answer reads the picture back to you: the text lines in reading order, each with its box and a confidence score, from a PP-OCR model pair you supply. The annotation never touches the image bytes.

Accept: application/json; ocr=1

Provenance, checked and signed

Meta reports the C2PA Content Credentials a source carries: manifest present, whether it validates, who signed it. With your own certificate, still JPEG, PNG, WebP, and AVIF outputs are signed as served, the source recorded as an ingredient, so the chain survives the transform.

CRABCROP_C2PA_CERT · CRABCROP_C2PA_KEY

Sealed URLs for public links

For links that stay public but unreadable: the whole recipe, operations and source, encrypted into one opaque token in the signature slot. Only the server opens it, and it serves the same render as the readable spelling.

s1.<token>/photo.jpg

A source policy decides what loads

The server fetches only from origins the operator allows, and /explain reports on any signed URL instead of serving it. Presets keep long recipes short, named once on the server and reused in every template.

GET /explain/<signature>/...

Running in a minute.

Two images, one command each. The plain image serves and transforms; the AI image adds the models for the finishing stages.

$docker pull ghcr.io/dayvson/crabcrop:0.9.8
$docker pull ghcr.io/dayvson/crabcrop-ai:0.9.8
$curl --proto '=https' --tlsv1.2 -LsSf https://github.com/dayvson/crabcrop/releases/latest/download/crabcrop-installer.sh | sh
$cargo install crabcrop

Sign a URL, from any stack.

Every URL carries an HMAC-SHA256 signature over the operations and the source, lowercase hex. Sign with the TypeScript or Python SDK, the crabcrop-url Rust crate, or plain curl: same inputs, same URL.

printf '%s' 'crop:1200x630:smart/filters:format(webp):quality(80)/https://example.com/photo.jpg' \
  | openssl dgst -sha256 -hmac 'demo-secret'
# SHA2-256(stdin)= ca3d1f22f4cc3860926608df02383f46dcf74af9a4e1bc26b1a00c644f55f300
import { buildURL } from "@crabcrop/url";

const url = buildURL({
  base: "https://img.example.com",
  secret: "demo-secret",
  operations: "crop:1200x630:smart/filters:format(webp):quality(80)",
  source: "https://example.com/photo.jpg",
});
from crabcrop_url import build_url

url = build_url(
    base="https://img.example.com",
    secret="demo-secret",
    operations="crop:1200x630:smart/filters:format(webp):quality(80)",
    source="https://example.com/photo.jpg",
)
use crabcrop_url::{build_url, sign};

let signature = sign(secret, "crop:1200x630:smart/filters:format(webp):quality(80)/https://example.com/photo.jpg");
let url = build_url(base, secret, "crop:1200x630:smart/filters:format(webp):quality(80)", "https://example.com/photo.jpg")?;
Note

Each snippet signs the same example with the sample secret demo-secret. Swap in your base, your secret, and your operations.

Note

The source can be a short root reference instead of a full URL, like root:photos/cat.jpg: the server expands it against an origin configured on the server, so the origin itself never appears in the URL.

Note

A URL can also be sealed: the whole recipe, operations and source, encrypted into one opaque token in the signature slot, for links that have to stay public but unreadable. The readable form stays the default. See sealed URLs in the docs.
